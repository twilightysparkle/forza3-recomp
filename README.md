# forza3

Static recompilation of Forza Motorsport 3 (Xbox 360) with the
[ReXGlue SDK](https://github.com/rexglue/rexglue-sdk) v0.10.0. The layout
follows [hl360-Forza2](https://github.com/0herculabs/hl360-Forza2).

No game files are included. You supply your own dump.

## Layout

| Path | Purpose |
|---|---|
| `forza3_manifest.toml` | Codegen config: function boundaries, rexcrt mappings, hooks |
| `src/` | Host code: `main.cpp`, `forza3_app.h`, and your overrides of `sub_<addr>` functions |
| `generated/` | Codegen output (`rexglue.cmake` is regenerated by the SDK; do not edit) |
| `assets/` | Your extracted game (`default.xex` + data) |
| `userdata/` | Saves, profile, installed Disc 2 content, caches (created on first run) |
| `build.cmd` | Configure + codegen + build |

## Running

Just run `out\build\win-amd64-relwithdebinfo\forza3.exe` (double-click works).
With no arguments it looks for `assets\default.xex` next to the exe or in up to
five parent folders, and keeps user data in `userdata\` beside that `assets\`
folder (`src/default_paths.cpp`). `--game_data_root=<dir>` and
`--user_data_root=<dir>` still override them. Logs go to `<exe dir>\logs\`.

The SDK is built and installed at `..\rexglue-sdk\out\install\win-amd64`.
To rebuild it, run `..\build_sdk.cmd`.

## Workflow

1. Extract FM3 disc 1 into `assets\` and check that `assets\default.xex` exists.
   Ultimate Collection disc 1: title `4D53084D`, media `6F74359D`, version 8,
   XDK 2.0.8276. Disc 2 (content install) goes in `assets\Disc 2\`.
2. Run `build.cmd`. The first run will fail in codegen with unresolved calls.
   That is expected.
3. For each unresolved call, find the function in a disassembler and add it
   under `[entrypoint.functions]` in the manifest. Run
   `..\rexglue-sdk\out\install\win-amd64\bin\rexglue.exe codegen forza3_manifest.toml --force`
   to generate output anyway while you work through them.
4. Locate the statically linked XAPI fiber functions and map them under
   `[entrypoint.rexcrt]` (Forza 2 needed this).
5. Build, run, and fix runtime problems by overriding the weak `sub_<addr>`
   functions in `src/`. Check whether the dot-product overflow
   fix from ForzaHorizon1-ReImagined (`patches/rexglue-sdk/`) is needed.

## Tools

Run these with `python -E -P` (needs `pip install --user cryptography capstone`):

- `tools/xexinfo.py <xex>`: header, title ID, static libraries
- `tools/xexdis.py <xex> <out.bin> addr[:before[:after]] ...`: decrypt the image, check pdata, disassemble
- `tools/scan.py <out.bin> <start> <end> [all]`: word-by-word listing that skips VMX128 words
- `tools/fibers.py <xex> <out.bin> addr ...`: find KTHREAD+0x164 (fiber) accesses and branch callers


## Settings menu (F2)

Press **F2** in game (a hint shows for the first seconds after launch). Tabs:

- **Display**: fullscreen, window size, vertical sync, 16:9 letterboxing,
  upscaling filter (bilinear / AMD CAS / AMD FSR 1).
- **Graphics**: internal resolution (1x/2x/3x, experimental), anisotropic
  filtering, extra FXAA, render-to-texture readback (keep "Balanced" = `some`).
- **Controls**: keyboard controls on/off, mouse camera and sensitivity, and
  every key binding with Set / Add (alternative key) / Clear / Default and a
  warning for keys used twice or taken by an overlay hotkey.
- **Game & sound**: console language, mute, list of hotkeys.

Changes apply at once where the emulator allows it; settings marked
*restart* only take effect after a restart, which the footer lists along with a
**Save and restart** button. **Save** writes the settings that differ from the
shipped `forza3.toml` to `forza3.user.toml` next to the exe, loaded on top of
it at startup (command-line flags still win); the build never touches it, and
deleting it returns to the shipped settings. **Reset to defaults** goes back to
`forza3.toml`. The game gets no controller input while the menu is open. Mouse,
or keyboard: arrows + Enter/Space, PgUp/PgDn switch tabs. Code:
`src/settings_menu.cpp`. F4 still opens the SDK's list of every cvar.

## Keyboard controls

Defaults set in `config/forza3.toml` (copied next to the exe on every build; edit
it there, not the copy); players can rebind in the F2 menu. Keys act as full
on/off controller inputs.

|---|---|---|
| W / S | Right / left trigger | Throttle / brake |
| A / D | Left stick left / right | Steering |
| Arrow keys | D-pad | Menu navigation |
| Space, Return | A | Confirm |
| E, Backspace, Escape | B | Back |
| Q, X | X | |
| R, Y | Y | |
| V / C | LB / RB | |
| Shift + arrows | Right stick | Look around |
| Shift + W / S | Left stick up / down | |
| F / G | Left / right stick click | |

The game's on-screen button prompts tell you what each controller button does.
F2 opens the settings menu; the SDK reserves F3 (debug overlay), F4 (all
cvars), F7 (achievements) and Backtick (console). A plugged-in controller works
as well.

## Disc 2 (bonus content)

Disc 2 is 8 content packages (STFS, type `00000002`) plus an installer XEX; the
game's own "insert Disc 2" flow needs a tray swap, so it is skipped. Instead,
`src/disc2_install.cpp` installs the packages at startup (before the game thread
runs) via the SDK's `ContentManager::InstallContent`, from
`assets\Disc 2\Content\0000000000000000\4D53084D\00000002\` into
`<user_data_root>\0000000000000000\4D53084D\00000002\`. A package counts as
installed once its `Headers\00000002\<name>.header` exists, so later launches
skip it. The game then enumerates all 8 and mounts them as `DLCRoot0:`..`DLCRoot7:`.
Failed opens of `stringtables.xml` / `media\db\patch\` on some roots are optional
probes for files those packages don't contain.

## Runtime fixes needed to reach a race

- **setjmp/longjmp** (`setjmp_address`/`longjmp_address` in the manifest): FM3's
  libjpeg longjmps out of decode errors. Unmapped, the guest longjmp "returns"
  with the wrong frame's registers and crashes in `read_markers`
  (`sub_824E9048`, null + 0x1A4) during the R8 showcase.
- **Utility drive** (`src/utility_drive.cpp`): the race streams its replay to
  `cache:\replay_stream`; the SDK mounts no `cache:` device, so the open fails and
  `sub_828678F0` dereferences null. `cache:` is now `<user data>\utility_drive`.
- **Crash dumps** (`src/crash_dump.cpp`): unhandled faults write
  `<exe dir>\crashdumps\forza3_<time>.dmp`. Inspect with
  `lldb forza3.exe -c <dump> -o "thread backtrace"`. The `sub_XXXXXXXX` frames are
  guest functions, and `$rdi` in recompiled frames points at the guest registers
  (order r3, r0, r1, r2, r4..r31, 8 bytes each).
- `tools/drive.ps1` scripts launch, key presses and window captures for testing.

## Graphics

- **SDK patches** (`patches/rexglue-sdk/`, from ForzaHorizon1-ReImagined, all
  matching upstream Xenia): applied on the `forza3-patches` branch of
  `..\rexglue-sdk` with `git apply`, then `..\build_sdk.cmd`. After rebuilding the SDK,
  delete `generated/default/codegen.stamp` so codegen regenerates (0025 changes
  emitted dot products).
- **Road flashing (fixed):** `readback_resolve = "some"` in
  `config/forza3.toml`. Without resolve readback, CPU writes near FM3's shadow
  maps make the emulator re-upload those pages from stale guest memory, so the
  shadow maps get corrupted in page-sized blocks (grid/dash patterns on the road,
  flashing while driving). Found with the texture dump and confirmed by A/B runs.
- **Car shadow block (fixed, SDK patch 0100):** the dark block around the car that
  rotated with it. FM3 renders a top-down variance shadow map of the car (k_16_16,
  4x MSAA) and resolves it with exp bias +10 as **SignedInteger** (0x1BE83000), then
  samples it as signed **integer** num_format with exp_adjust -15 and tests
  `>= 0.99` to build a 16_16 mask (0x1BF83000) the ground shader multiplies in.
  Two SDK bugs broke this (found by diffing against an instrumented xenia-canary,
  which renders it correctly):
  1. The full resolve shaders ignored `copy_dest_number` and packed every fixed
     format as an unsigned fraction, so the map saturated to 0xFFFF (-1). The
     resolve shaders are rebuilt by `tools/build_resolve_shaders.py` from upstream
     Xenia sources (whose EDRAM MSAA layout matches the SDK; canary's doesn't, and
     its shaders made every MSAA resolve blocky) with canary's number-format
     packing ported in; `GetCopyShader` also keeps signed/integer destinations off
     the raw fast path.
  2. Texture fetches ignored integer num_format, returning the normalized value
     (32767 sampled as 1.0, then x 2^-15). The DXBC translator now scales by
     2^(w-1)-1 (signed) or 2^w-1 (unsigned) for 8- and 16-bit-per-component
     formats when the fetch constant's num_format bit is set.
  To reapply after an SDK update: `git apply` the patch, then
  `python tools\build_resolve_shaders.py <xenia upstream> <xenia-canary>
  ..\rexglue-sdk\src\graphics\shaders\bytecode\d3d12_5_1` (Windows SDK FXC).
  Ruled out on the way: float24 depth conversion, ROV, 2x MSAA, half-pixel
  offset, depth transfer test, direct host resolve, `clear_memory_page_state`,
  `readback_memexport`.
- **Texture dump** (SDK patch): `--texture_dump_dir=<dir> --readback_resolve=full`,
  then create `<dir>\TRIGGER` in game: the next guest frame's sampled textures are
  logged to `index_N.txt` (draw, shader hashes, fetch constants) with raw guest
  data in `tex_*.bin`. `tools/texdecode.py <index> <bin>...` un-tiles and writes
  per-channel PNGs. Add `--dump_shaders=<dir>` to match shader hashes.

### PIX captures

Launch with `--pix_gpu_capturer=true` (loads PIX's `WinPixGpuCapturer.dll` before
the D3D12 device is created), then press **F9** in game: the next
`pix_capture_frames` (default 4) host frames are written to
`<exe dir>\pixcaptures\forza3_<time>.wpix`. One host frame holds only part of a
game frame, hence 4. `pixtool attach` doesn't work (PIX only attaches to
processes it launched). `pixtool open-capture <wpix> save-screenshot / save-event-list /
save-resource --global-id=N` work for colour targets, but not for the D32_S8X24
depth used for float24 or for sampled textures, so use the PIX GUI for those.

FM3 renders 720p in two EDRAM tiles (top half first).
